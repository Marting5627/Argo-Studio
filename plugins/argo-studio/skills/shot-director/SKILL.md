# 分镜导演稿

将外部聊天已完成的逐镜正文保存到工坊自定义稿，不再要求 Argo 导演重写正文。这不是单 Shot 正式导演历史的恢复工具。

先用 `argo_tools` 按 `area=workshop` 查询所需工具，再按完整 `tool` 读取该项输入/输出合同；不遍历全部工具。工坊调用使用 `argo_workshop`，参数为 `{tool:"原生工具ID",arguments:{…}}`。

每个 Shot 只有一套当前提示词，分“自定义／导演稿”两来源；A–D仅选择生成候选，正文不带 `lane`。修改模型、候选或参数时，先读 `generation.inspect` 与当前选项，再用 `generation.proposal` 提交单项或多项差异；省略保持、null拒绝。清型号用 `clearModel:true`，移除型号参数用 `clearModelParameters`，取消全部候选用 `candidateLanes:[]`。接受提案后在生成板核对；点击“覆盖参数”由同一 `generation.apply` 一次确认后直接保存并回读新版本，不进入本地草稿恢复流程。生成仍分别确认报价与提交。外部不能修改设置或读取本地模型连接配置；业务渠道、模型、缓存余额和有效报价沿工坊合同读取。

1. 保留已确认的正文、顺序和引用，明确每镜新建或现有目标、时长、比例及参数策略；正文写入目标 Shot 的共享自定义稿，保留导演稿。当前工坊渠道由宿主绑定，`importScript` 没有 `channel` 字段。按当前工具 Schema 组织输入，时长使用毫秒且合计一致，`localID` 唯一；明确新建才省略 `shotID` 或传 null，现有目标使用稳定句柄，全局目标必须明确。本次新计划使用新的 UUID `planID`，它不是批准。
2. 对话沿用当前工程完整软件编号，如 `Shot01`、`Shot03-C2-A`、`图片001`。用 `argo_resolve_object` 核对真实对象；不从顺序或同名猜目标。工程、目标或来源变化后重新核对，旧批准不挪给新计划。
3. 需要理解素材时先调用 `argo_read_asset_media` 读取真实来源；保留同一对象、完整编号和 `sourceRevision`，传回时复用绑定。视频抽样不等于逐帧检查或音轨识别。`references` 省略或 null 保留原引用，`[]` 才是清空，非空列表替换引用并明确角色和用途。内联 `mentions` 仅绑定本镜列表，`location`/`length` 按原文 UTF-16 计算，`token` 完全一致；无内联引用时传空数组。
4. 保留现有参数时，先逐目标调用 `generation.inspect`；必填时长和比例取用户稿件或该目标原生实值，不猜测、不复制另一镜，缺失时询问。按用户意图填写 `parameterPolicy`：`apply` 应用生成时长和比例，`planningOnly` 仅保留规划、不改生成参数。原生能力不支持时报告差异，待用户明确调整；不得为通过校验擅自切成 `planningOnly`。其余模型、候选集合、其他稿件和正式历史沿原生保留规则执行。
5. 调用 `generation.importScript`，正文留在聊天中核对，真正客户端批准表单仅确认目标、操作摘要和影响范围，再由原生事务保存。正文同意不是批准，客户端不支持确认时不写入。此流程不调用上传、报价或视频生成，也不把导入理解成这些动作的授权。
6. 获得 `operationRef` 后用 `argo_operation_status` 查询同一操作，按原生回执报告实际规范编号及新建/更新结果。只有 `saved` 才报告保存成功；保存后刷新或聊天模型失败不能重做导入。等待、超时或 UNKNOWN 时先核对原操作；`operationRef` 仅当前连接有效，失效、撤权、取消或暂停后，只读核对已保存状态与真实回执，证据不足即停止，不换 `planID` 重做。

复用原生预检、批准、唯一 writer 和回执，不绕过业务校验。分别说明已保存、未执行和失败部分；工坊保存不等于正式导演稿恢复或视频生成。
