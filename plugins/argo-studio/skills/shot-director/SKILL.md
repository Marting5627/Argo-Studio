# 分镜导演稿

将外部聊天已完成的逐镜正文保存到工坊自定义稿，不再要求 Argo 导演重写正文。这不是单 Shot 正式导演历史的恢复工具。

仅改模型、选中候选集合或生成参数时，沿当前工具目录使用 `argo_generation_dinspect` / `argo_generation_dprepare`，不调用本正文工具；`lane` 是正文通道，不是选中候选集合。

1. 保留已确认的正文、顺序和引用，明确每镜新建或现有目标、正文通道 `lane`、时长、比例及参数策略。当前工坊渠道由宿主绑定，`importScript` 没有 `channel` 字段。按当前工具 Schema 组织输入，时长使用毫秒且合计一致，`localID` 唯一；明确新建才省略 `shotID` 或传 null，现有目标使用稳定句柄，全局目标必须明确。本次新计划使用新的 UUID `planID`，它不是批准。
2. 对话沿用当前工程完整软件编号，如 `Shot01`、`Shot03-C2-A`、`图片001`。用 `argo_resolve_object` 核对真实对象；不从顺序或同名猜目标。工程、目标或来源变化后重新核对，旧批准不挪给新计划。
3. 需要理解素材时先调用 `argo_read_asset_media` 读取真实来源；保留同一对象、完整编号和 `sourceRevision`，传回时复用绑定。视频抽样不等于逐帧检查或音轨识别。`references` 省略或 null 保留原引用，`[]` 才是清空，非空列表替换引用并明确角色和用途。内联 `mentions` 仅绑定本镜列表，`location`/`length` 按原文 UTF-16 计算，`token` 完全一致；无内联引用时传空数组。
4. 保留现有参数时，先逐目标调用 `argo_generation_dinspect`；必填时长和比例取用户稿件或该目标原生实值，不猜测、不复制另一镜，缺失时询问。按用户意图填写 `parameterPolicy`：`apply` 应用生成时长和比例，`planningOnly` 仅保留规划、不改生成参数。原生能力不支持时报告差异，待用户明确调整；不得为通过校验擅自切成 `planningOnly`。其余模型、候选集合、其他稿件和正式历史沿原生保留规则执行。
5. 调用 `argo_generation_dimportScript`，正文留在聊天中核对，真正客户端批准表单仅确认目标、操作摘要和影响范围，再由原生事务保存。正文同意不是批准，客户端不支持确认时不写入。此流程不调用上传、报价或视频生成，也不把导入理解成这些动作的授权。
6. 获得 `operationRef` 后用 `argo_operation_status` 查询同一操作，按原生回执报告实际规范编号及新建/更新结果。只有 `saved` 才报告保存成功；保存后刷新或聊天模型失败不能重做导入。等待、超时或 UNKNOWN 时先核对原操作；`operationRef` 仅当前连接有效，失效、撤权、取消或暂停后，只读核对已保存状态与真实回执，证据不足即停止，不换 `planID` 重做。

复用原生预检、批准、唯一 writer 和回执；真实业务校验不能按 QA 限制绕过。把已保存、未执行和失败部分分别说明，不把工坊保存说成正式导演稿恢复或视频已生成。
